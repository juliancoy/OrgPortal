# Live MCP and OAuth statistics

Admin → Statistics includes a live operational panel, separate from automated test results. It reads OrgPortal `/api/admin/mcp-statistics` (portal administrator authorization) and PIdP `/admin/oauth-statistics` (live primary system administrator authorization). Both return no-store JSON. The browser refreshes every 30 seconds while visible and on window focus. Today, 7-day and 30-day windows use UTC dates and include the partial current day.

OrgPortal counts MCP request methods, normal initial authentication challenges, rejected tokens, permission denials, rate limits, HTTP/server errors and JSON-RPC tool errors. PIdP counts registration, authorization, consent, browser handoff/linking, token exchange or refresh, introspection, revocation, Google/GitHub login and calendar authorization callbacks. Token exchanges and refreshes share a stage. OAuth redirects are reported as redirects, not completed logins. Consent denial is distinct from service failure. A successful response does not establish that a whole end-to-end workflow succeeded.

Stored dimensions are date, fixed allowlisted stage and outcome. Values are count, summed duration and maximum duration. No raw URLs, tool names/arguments/results, OAuth bodies, authorization codes, token hashes, client IDs, subjects, IP addresses, emails, browser IDs or provider errors are stored. Supporting tables are private, excluded from public replication and (for OrgPortal) immutable journals, and cleaned in bounded retention batches after 30 UTC dates. Reads filter the time window immediately.

Counters are best effort; a telemetry-storage failure does not block authentication or tool handling and emits only a sanitized availability warning. Requests that never reach the instrumented service, infrastructure outages and interrupted streaming response bodies are outside these counts. Request duration measures handler response preparation, before the statistics write, not client network latency or complete streamed-body duration. Counts aggregate all tenants sharing that service database and span releases. They are not unique users, uptime measurements, provider inbox-delivery evidence, test results or OAuth conversion rates.
